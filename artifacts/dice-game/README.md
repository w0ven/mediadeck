# 骰局 · 开发交付与验真

仅本地源码实现与模拟测试。新插件 `dice` 默认关闭，未部署、重启、修改线上配置或向Telegram发送测试消息。

## 接入

- 在现有授权群/话题发送 `/骰局`（别名 `/dice`）；`/骰局帮助`、`/游戏`及个人菜单均可发现玩法。
- 群卡明确公布承诺、固定drand轮次和封盘时间；收到开局卡准确发送回执才开放扣款。
- 私聊使用真实操作者身份和有效绑定账号。七池、多项草稿、10/50/100快捷金额、回复金额卡输入整数、确认及追加均接通。金额回复携带卡内输入凭据，旧回复和重复消息不能串选项。
- 90秒封盘，最低1分，0抽成，无人为金额上限；整数存储上界、总池容量和余额检查保留。
- 共用原积分账本、`economy_write`事务和`CashBook.reserve`。资金进入独立dice托管，结算直接经原账本退还，不借用牛牛/黑白板资金池，不改变其资金语义。
- 固定结果和分池结算分别持久化；所有池的返还在单一事务中完成。结算中断回滚，已有结果仅恢复原结果。账户缺失或整数溢出时资金原地保留并显示异常，不猜测收款人。
- 群最终战报仅列可点击昵称和全局净盈亏，固定25人分页；私聊发送本人分池结算，亦可从战报链接查看逐项投注、命中、奖金、退款、净盈亏和开奖证据。

## 签名与三骰推导

选型：drand主网 `pedersen-bls-chained`，G1公钥48字节、G2签名96字节。使用 `py-ecc==8.0.0` 的 `G2Basic.Verify`，包含曲线点/子群验证；不是仅信任公网JSON。

固定参数：

- 链：`8990e7a9aaed2ffed73dbd7092123d6f289930540d7651336225dc172e51b2ce`
- 公钥：`868f005eb8e6e4ca0a47c8a77ceaa5309a47978a7c71bc5cce96366b5d7a569937c529eeda66c7293784a9402801af31`
- 创世时间：1595431050；周期30秒。
- 轮次时间：`genesis + (round - 1) × period`。
- 开局固定严格晚于封盘的第一轮；镜像只查询该链该轮，绝不换轮。
- 签名消息：`SHA256(previous_signature字节 || round的8字节大端编码)`。
- 签名域由G2Basic固定为 `BLS_SIG_BLS12381G2_XMD:SHA-256_SSWU_RO_NUL_`。
- randomness必须严格等于 `SHA256(signature字节)`。

规则/算法版本：`dice-pools-v2-drand-v1`。

开局生成32字节服务器种子，按小写hex保存。承诺为 `SHA256(hex解码的种子)`。验签后推导：

```text
seed = SHA256(ASCII(JSON紧凑数组[
  版本, 链标识, 整数轮次, 种子hex字符串, 局ID字符串, randomness的hex字符串
]))
stream块 = SHA256(seed字节 || 8字节大端counter)
counter从0递增。按字节顺序，只接受0–251，点数=byte%6+1，取前三个。
```

JSON使用 `ensure_ascii=True, separators=(',', ':')`，无空格、无换行。种子承诺、链、公钥、轮次、原签名、previous_signature、randomness、服务器种子、seed、三骰和时间均可在本人私聊“开奖验真”读取。开盘期间不公开服务器种子。

最大余数分配先聚合“用户＋池”：奖金向下取整后按精确整数余数降序补1分。余数相同按 `SHA256(ASCII(JSON紧凑数组[seed小写hex, 池ID, 稳定账户ID字符串])))` 字节升序；极端哈希相同再按账户ID排序。拆分同账户注单不改变结果。

固定测试向量：链真实轮次6543504，服务器种子`00`重复32次，局ID`00`重复12次，真实签名见 `backend/tests/test_dice.py::SIGNED`：

```text
seed = f9d4db2a375f128df3cbf209d137b0727ee72c500da53e8f64bf1b4ac105e1ea
骰子 = [1, 1, 2]
```

## 恢复与清理

- 未取得有效数据，封盘后最多等待600秒；后台恢复时按持久化时间退款。停机期间无法执行的退款在恢复后执行，不能承诺进程停机时仍实时付款。
- 开局/私聊卡丢失发送ACK：不自动复制发送；点击原Bot原聊天/话题中的当前按钮可校验并补记准确回执。
- 最终战报发送结果不确定：后台插件显示待核实任务。人工确认战报真实消息ID后可登记；也可明确勾选重发，但Telegram不提供发送幂等，可能重复送达。恢复操作有审计记录，不触发二次结算。过程卡不接受手填删除目标。
- 全部群战报页确认送达后，才删除精确记录的开局卡；最终战报不加入清理队列。
- 骰局专属删除kind，不借用个人账号卡/管理卡清理。可信命令、金额输入、临时反馈通常60秒后删除；私聊过程卡保留至本次会话过期（至少15分钟），本人结算反馈15分钟后删除。期限明确持久化，重启恢复。
- 删除失败按原精确目标重试。权限拒绝、48小时删除时限或丢失ACK且无可靠消息ID时不能保证删除；不扫描历史、不猜ID。后台显示清理状态，人工运行插件可重试仍在删除时限内的阻塞任务。
- 本实现未创建独立群配置，也未读取生产凭据。新venv仅位于本工作树 `.venv`。
