# Bot 验收修正：求片视角与密码选择

基于 `v0.34.1 / 3ad63e1`，本轮只本地实现与验证，未推送或部署，未访问生产凭据或更改生产密码。

## 求片原卡变成管理卡：已确认根因

按 debug-log-first，先使用真实 Bot handler、隔离 SQLite、模拟 Telegram 固定请求内容，只改变账号角色：

- 普通用户的原请求卡只有详情、记录、补充、撤回、我的求片。
- 加上 uploader/admin 后，同一个原消息立即新增接受、拒绝、询问、内部备注、管理员纠错/退额度及工作台。
- 重启后刷新仍出现这些按钮；持久化 payload 只有 `rid`，没有入口视角。

根因不是扣次或工单状态，而是 `_rq_detail` 使用账号当前角色推断视角，后续详情导航、文本回复、通知刷新再次按角色重建。本人同时是上片员时，外发通知还可能抢占该私聊的活动卡。

### 修正

- 将 `user/staff` 入口视角存入现有卡片 payload，列表、详情、完整详情、沟通记录、输入、通知和重启刷新沿用该视角。
- **角色只决定能否进入/执行管理功能，不决定用户原卡的展示。** 本人从用户入口提交/关注，即使有 admin/uploader 角色，也始终显示普通用户卡。
- 上片员独立通知与工作台明确为 staff 视角；管理员纠错、内部备注等只在此视角显示，并继续经过服务端角色、所有权、revision 和单次操作校验。
- 外发通知在脱离当前用户菜单的会话上下文执行，不覆盖原卡或抢走密码输入卡。
- 旧持久卡若属于本人且缺少视角记录，无法可靠区分旧混合卡来源，保守恢复为用户卡；管理入口可从工作台重新打开，不猜测提升权限。
- 工作台每条按钮显示 **工单号＋片名/剧名（年份）**，长标签截断，详情显示完整名称；缺少片名时明确“暂未获取片名”及编号。按钮与目标工单逐条验证。

上轮简化、剧集全部季/文字指定季原卡提交、关注、接受即终结、选填拒绝理由、原有额度和门禁均保留。数据库字段、服务层工单权限和 Web/API 未修改。

## 密码：随机或自定义，明确选择后最终确认

### 本人重置

我的账号 → 重置密码 → **随机生成 / 自定义密码** → 最终确认 → 执行一次并在本人私聊显示新凭据。

- 未选择方式前不生成密码，不修改旧密码。
- 随机方式沿用原 12 位字母数字生成器，选择后只生成一次；旧按钮或双击不能重复生成/执行。
- 自定义至少 6 位，沿用现有密码 API 最低长度；**不 trim、不规范化或替换字符**，包括首尾空格。私聊显示采用 HTML 转义，发送给 Emby 的仍是用户输入原值。
- 最终确认说明旧密码失效、客户端需更新、权益不变。执行前后重验 TG 绑定；缓存失效和审计仍使用现有路径。

### 注册

现有赠送、管理员预授权、邀请码或卡密入口 → 用户名 → **随机生成 / 自定义密码** → 确认用户名、密码方式/值、用户组和有效期 → 创建并设置密码。

用户名输入不再直接开户。最终确认后才进入原有注册锁、资格重新核验、创建/设置密码、事务消费资格及失败回滚；群赠送回执仍仅在真正注册成功后生成，不含密码。

### 安全边界

- 自定义密码只在本人私聊输入。输入错误可在原卡重试；`/cancel`、`/start`、返回菜单、返回选择方式均撤销对应等待，不执行改密或注册。
- 输入按原始文本处理，不会把长得像赠送凭证或含 `@` 的密码误当邀请码/其他 Bot 命令。明确的取消命令保留取消语义。
- 密码和待确认资料仅保存在既有短期内存会话中；重置沿用 2 分钟期限，注册 10 分钟。**不写入 callback、工单、配置或审计日志，也不提供查询旧密码功能。**
- 成功凭据仅回到本人私聊，群内不展示；自定义密码的确认显示和成功显示均不改变原值。
- 没有新增 Bot 管理员代重置权限；现有 Web 管理员重置与目标隔离保持原样。
