# 求片中心

## 产品语义

- 用户确认提交后为 **待处理**（`open`），创建工单与扣一次月额度在同一事务内。
- 上片员点击 **接受请求** 即为终态 **已接受**（`accepted`），之后手动安排下载。没有接单、处理中、二次完成、待上架或已上架。
- **已拒绝**（`rejected`）的理由完全选填；空理由不显示、不生成默认理由。
- 用户仅可在待处理时撤回为 **已取消**（`cancelled`，Bot 显示已撤回）。Web 询问/回复不改变待处理状态；Bot 不再提供沟通功能。
- 不自动下载、不连接 MoviePilot、不增加积分收费。接受本身不证明下载或入库；已有只读入库通知机制不变。接受通知为：
  > 已接受，等待下载并入库。

## Bot

- 用户私聊 `/requests` 或主菜单「求片中心」。上片员私聊 `/uploader`（兼容 `/req`），只需 uploader 角色，不要求 admin；管理员也可处理。
- 用户入口的本人求片卡不随 admin/uploader 角色变成管理卡；视角随卡片持久化。管理能力仅在独立上片员通知/工作台，通知刷新不会抢占原用户卡。工作台逐条按钮显示片名＋工单号，而非通用「详情」。详见 [视角与密码验收修正](bot-view-password-acceptance.md)。
- 已允许交互的用户群中 `/requests` 只提供私聊深链，不发送工单内容。本轮没有启用专用处理群、改动现网配置或新增自动外发目标。
- 中英文片名搜索，电影/剧集、年份筛选与候选分页；TMDB 链接或纯数字编号。纯数字必须选择类型，明确类型永不回退到同编号的其他作品。
- 候选、工单和上片员新请求通知优先使用海报；片名直接链接经类型/正整数编号校验的 TMDB 页面，HTML 转义保留，不放独立 TMDB 按钮。选片可看短简介；提交后不再重复原名或长简介，不再增加「详情」页面。图片失败文字回退；元数据失败明确「暂未获取片名」，保留类型及编号。
- 用户搜片 → 选中影片 → 确认求片。电影默认整片；剧集确认卡默认勾选「全部季」，也可点「指定季」发送 `1,3,5-7`。输入后编辑同一卡显示规范化季范围及提交按钮，错误同卡提示可重输，可修改/返回，不再多跳一层确认页。纯数字编号仍需明确电影/剧集类型。
- Bot 已移除版本、清晰度、字幕、配音、备注等要求选择/编辑页，不再逐项填写。最终确认保留片名、年份、类型、季范围（剧集）和扣一次额度说明；已有相同待处理请求直接关注，不扣次。历史工单已有季集、版本、字幕等字段及备注原样保留，当前工单卡直接展示；超长旧海报结果保留醒目摘要，从列表重新打开可看完整信息。
- 媒体库仅在选片时做只读、按用户权限范围的辅助查询；可打开现有条目详情；剧集仍可选择所需季范围。查询失败或不完整明确显示未知，不当作没有，不阻止提交。
- 用户列表默认本人求片，工作台默认只看待处理。每单只有一个进入按钮；状态/类型/搜索收进筛选页，候选类型/年份也收进筛选页。只有存在前/后页才显示分页；无筛选不显示清除。我的求片、我的关注和工作台集中在求片中心。
- 本人待处理卡仅撤回/返回（撤回仍须确认），本人终态仅返回；其他用户可免费关注原单。上片员待处理仅接受/拒绝/返回，终态仅返回工作台。接受仍一步终结；拒绝页的常用理由按钮明确标注「拒绝」，点击即完成，其他原因才输入。无理由拒绝仍可用。
- Bot 已移除询问、回复、内部备注与沟通记录入口；历史按钮及待输入草稿明确停用，不执行原操作，不删除历史。Web 沟通/记录能力不变。
- 工单最顶部独立粗体区分「待处理」与「已处理 · 已接受/已拒绝/已撤回」，正文展示真实处理结果、权威状态事件中的处理人/时间与拒绝原因；事件缺失明确未知，不编造。接受不等于已入库。
- 升级前未提交的复杂向导必须按简化流程重新确认，旧编辑按钮只打开原工单详情，不改变已保存要求；旧拒绝输入曾承诺的二次确认仅为该旧会话保留，避免升级后把普通文字意外解释成拒绝。
- 管理员纠错、人工退回额度与失败通知手动重试仅保留已有 Web 后台入口；Bot 旧按钮/草稿不再执行。服务/API 和内部操作记录不变；纠错不自动退款，拒绝/撤回也不自动退款。
- 普通首页六入口（两列三行）：我的账号/播放线路、求片中心/积分背包、排行榜/帮助。账号合并状态、流量/带宽、同时播放上限、已登记设备数、累计观看及积分，未知不编零；私聊保留备注和有效下载/转码权限，内留设备/改密/换绑；准则归帮助；管理员才额外显示管理入口。原有效命令及私聊深链继续可用。
- `/kk` 主卡只保留续期、已核实的禁用或解除禁用、更多管理、刷新、返回/关闭；远端状态未知只刷新；远端可知且任一本地/Emby 来源实际禁用时明确提供解除禁用，包括仅远端或仅本地禁用，不把两端不一致当作禁止解除。两端都未禁用才提供禁用；执行前仍重新读远端状态，解除不续期、不重置用量、不消除到期/耗尽/待开通等剩余限制。用户组/白名单、积分、资料/绑定、删除收进更多管理；actor/target/nonce/message/topic 绑定及一次性确认保留。切换更多管理取消隐藏确认。
- 普通功能页目标最多三行按钮，单一返回；商城/工单等列表条目、管理员额外入口及必要门禁/确认除外。v0.39.4 群临时查询清理、业务通知和 Web/计费/处罚/观看统计不变。

## 数据、兼容与并发

`request_schema.py` 在已有数据库上增列/建附属表，不重建或删除历史工单：

| 原状态 | 新状态 | 兼容说明 |
| --- | --- | --- |
| open | open / 待处理 | 保留待处理 |
| claimed | accepted / 已接受 | 原已接单对应新的接受终态 |
| done | accepted / 已接受 | 不推断已下载、入库或上架 |
| rejected | rejected / 已拒绝 | 原理由原样保留 |

- 原状态保存在 `legacy_status`；原用户、备注、处理人、时间、额度记录保留。迁移不扣次、不生成历史通知。迁移可重复执行。
- 去重键为作品 ID + 电影/剧集类型 + 规范化需求（范围、季集、版本、清晰度、字幕、配音）。普通备注是补充沟通，不作为绕过去重的差异。
- 同需求待处理可关注原单，不新建、不扣次；额度用完仍可关注。已接受的相同需求提示等待入库，不再次扣次；可选择不同缺集或版本。
- 月额度沿用原有 UTC 自然月规则。人工退回每工单仅一次，只退原扣次月份，不能把已过月份的次数转入本月。
- SQLite `BEGIN IMMEDIATE` 与条件更新（`open` + `revision`）保证多连接竞争只有一人终结；修改需求/管理员纠错增加 revision，旧按钮不能终结新版本。
- Bot 操作能力绑定随机 token、私聊、消息 ID、账号、允许动作、工单 revision 和期限；输入/卡片持久化。离开/取消草稿撤销隐藏输入与草稿能力，重启可从列表恢复；越权、跨卡、过期、重复操作均重验。

## 通知与恢复

工单变更、沟通消息和通知 outbox 在同一事务提交。投递有租约与发送记录，失败自动重试，也可从 Web 手动重试；只重发未确认的通知，不重扣额度、不重做处理。接受/拒绝/撤回及管理员纠正通知求片人和关注者；询问/回复保留独立工单归属。处理后更新原操作卡及其他上片员持久卡、已打开的工作台列表。已有 `request_notices` 定位的历史群/私聊通知同步醒目结果并去旧按钮，编辑失败保留待重试 outbox，不假称全部已刷新。无持久消息 ID 的旧群消息无法回补，不猜 ID、不扫历史；本轮不新增群广播。历史沟通收据不被刷新抹掉。终态/后台纠正的异步结果通知同样采用醒目首行与片名链接，但保留该次 outbox 的状态/理由快照，处理人/时间通过 payload 中的现有事件 ID 关联；旧 payload 无关联证据时显示未知，不借后续处理人。原操作卡与异步通知在预览中分开展示，通知去重键/投递账本不变。

**Telegram 协议边界：** 已确认成功的投递不会再次发送，并发重试受租约互斥。但 Telegram `sendMessage/sendPhoto` 没有客户端幂等键；如果远端已发送而响应丢失，或进程在发送成功与本地落库之间崩溃，无法承诺绝对 exactly-once，恢复重试可能出现重复通知。工单终态和额度仍严格不重复执行。

## Web/API

Web 求片页面使用相同四状态、需求详情、沟通记录、内部备注、纠错与人工退回额度、通知投递状态/重试。

所有管理接口沿用现有管理员认证，不能通过 payload 冒用处理人：

- `GET /api/requests`：`status / media_type / search / limit / offset`
- `GET /api/requests/stats`
- `GET /api/requests/{id}`：详情、分页事件及通知投递状态
- `POST /api/requests/{id}/accept`、`/reject`：必传当前 `revision`；拒绝的 `note` 可空
- `POST /api/requests/{id}/messages`：`revision / body / internal / key`，消息 key 幂等
- `POST /api/requests/{id}/correct`：`revision / status / reason`
- `POST /api/requests/{id}/refund`：`reason`
- `POST /api/requests/{id}/notifications/retry`

旧 `/claim` 和 `/resolve` 返回 **410**，旧 Bot 按钮明确失效，绝不把旧「接单/已处理」按钮偷偷解释为新操作。

## Bot 简化验收（v0.34.0 后续修正）

仅调整 Bot 交互与展示；不改数据库/工单字段、服务层额度/权限/revision/幂等、门禁或 TMDB 配置，Web/API 无需修改。

- 电影、剧集全部季：从搜索结果到提交，原为「选片 → 需求范围 → 下一步 → 确认」4 次点击，现为「选片 → 确认」2 次。
- 剧集指定季：选片 → 指定季 → 文字输入 → 原卡提交；省去可选要求页和额外下一步。
- 上片员接受仍是 1 次点击；无理由拒绝仍为 2 次必要点击；自定义理由从 3 次点击加输入，减为 2 次点击加输入。
- 最终定向模拟 Bot/服务/TMDB/权限/上下文、导航及真实浏览器 Web 兼容回归 **276 passed**，覆盖季范围错误重输/修改返回/重启、扣次一次、关注及接受历史、旧要求字段保留、旧编辑/确认卡兼容和拒绝竞态。
